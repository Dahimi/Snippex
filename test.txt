A user sends a POST request to Snippex with a query and optional parameters — number of results, search depth, recency filter, domain filters. Snippex queries a search backend that returns ranked URLs with raw page content. For each result, we scrape and process the page content, then run a super fast custom extraction model (transformer-based) in parallel across all results. The model doesn't generate text — it identifies anchor phrases pointing to the most relevant passages, which we then locate, reconstruct verbatim from the source, and validate. This architecture is what makes the output hallucination-resistant: the model acts as a pointer, the reconstruction is deterministic. The final response is clean JSON: ranked results, each with title, URL, original search snippet, and our extracted passages with relevance scores.

Honestly, the pipeline is harder to replicate than it looks. It’s not just calling a model on some text — there’s a search layer, a scraping layer, an extraction model that identifies passages rather than generating them, a reconstruction step, and a validation step. Each part has been carefully engineered.

But the real defensibility, for me, is the data. Every request that goes through Snippex becomes a labeled example, so the model continuously improves in a way a new entrant can’t easily match. A well-funded competitor can copy the concept; they can’t copy the data.
